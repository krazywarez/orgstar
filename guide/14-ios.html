Overview

On first launch, a few screens introduce the app, ask for the folder of org files, and offer notifications, Calendar events and Reminders; each permission is asked for only when you choose it, and every one can be changed later in Settings. The app has three tabs, and opens on Folders until a folder has been added:

Agenda
the agenda over your folders, with capture.
Folders
the folders of org files you added. Each shows its subfolders and org files; tap a subfolder to open it.
Settings
where the app's settings come from.

The search button (the magnifying glass) at the top right of Agenda and Folders opens Search.

Files open in a reader first. The Edit button in the reader opens the editor. Both use the same open file, so an edit in the editor shows in the reader when you go back.

Folders and file access

orgstar on iOS works on folders you choose, in iCloud Drive or in another app's storage (for example a folder kept by a Syncthing client).

  1. Open the Folders tab and tap Add Folder (the folder icon with a plus).
  2. Choose a folder in the picker.

orgstar keeps access to the folder across launches. Each folder appears as a section listing its .org files by their path inside the folder. Remove Folder at the end of a section removes it from orgstar; the files stay where they are. An added folder that is empty also has Delete Folder…, which deletes it from disk too.

Swipe left on a file, or touch and hold it, to delete it. orgstar asks first. A file in iCloud Drive goes to Recently Deleted in the Files app; elsewhere it is removed. New File… and New Folder… under + at the top right make one in the folder shown, or with several added folders, in the one you pick; a file name without an extension gets .org. Empty folders are listed too and delete the same way; a folder with anything in it other than hidden files can't be deleted from orgstar.

Files that iCloud hasn't downloaded to the device yet appear in grey with a cloud icon. orgstar asks iCloud to download them and lists them as files once they arrive.

orgstar sees changes made by iCloud and by apps that use the system's file coordination, and reads every folder again each time you return to the app, since not every sync app reports its changes. An open file takes in changes from disk as described in Working alongside Emacs and other tools.

There is no way to open a single file from the Files app. Add the folder that contains it.

The reader

Tap a file in Folders or Search, or Open in File in an agenda entry's sheet, to read it.

  • Tap a heading to fold or unfold it, as TAB cycles it on the Mac. A chevron marks headings with content.
  • The file opens with the visibility its #+STARTUP line asks for, then each heading's VISIBILITY property when #+STARTUP sets a visibility. Drawers and blocks are folded as org-cycle-hide-drawer-startup and org-cycle-hide-block-startup say, or as the file's #+STARTUP says (hidedrawers, nohideblocks and the like). Tap a folded drawer's first line or its … to open it, and the first line again to fold it.
  • Text is styled as in the editor, in the theme's colours, font, size, line spacing and heading sizes, on the theme's background: TODO keywords, priorities, tags, emphasis, code, timestamps, links, and the code in src blocks. Text can be selected and copied.
  • The reader follows the editor's display settings (see Themes and display below): Show Markup, hidden emphasis markers, pretty entities, indentation, leading stars, inline images and truncated lines. Tables show at full width, without narrowed columns.
  • Tap a link to follow it. Links to headings and files in your folders open in the reader; web links open in the browser.
  • The toolbar has Outline (a list of headings to jump to), Export, and Edit.

The editor

Tap Edit in the reader. The title shows the buffer name, with • while there are unsaved changes. The tab bar is hidden while you edit.

The editor folds headings, drawers and blocks (tap a fold's … to open it, and an open drawer's first line to fold it), styles text with the theme from the configuration folder (see Themes and display below), and runs the same Org commands as the Mac. Autocorrection, smart quotes and smart dashes are off; spell checking follows spell-check in config.toml and is off by default; it leaves out code, links, dates, tags and keywords, as on the Mac. More ▸ Word Count shows the words, characters and reading time of the selection, or of the file.

The toolbar has:

Conflict
shown while the file and your edits conflict; opens the conflict sheet.
Undo
More
Commands, Clock In, Show Markup, Recent Entries, Export, Sync Conflict Copies, and Recovered Versions.

Messages from commands show at the top of the editor for a few seconds; tap one to dismiss it.

Every pane shows the same buffer: text typed in one shows in the others at once, and folds, narrowing and styles are the buffer's. The caret and scroll position are each pane's own, and so is undo: Undo in a pane undoes what was typed or changed in that pane. Each iPad window (scene), opened from the app switcher or by dragging the app from the Dock, has its own tabs, screens and panes over the same open files, so a file edited in one window shows the edit in the others. The pane commands aren't offered on iPhone or in a narrow window.

Saving

The iOS app always saves automatically: one second after you stop typing, when you leave the editor, and when the app goes to the background. The save setting doesn't apply on iOS.

Files that aren't valid UTF-8 open read-only; commands that would change them say so.

Themes and display

The editor and the reader use the theme set in the configuration folder's config.toml, stacked as on the Mac: the themes chosen with light-theme and dark-theme, then the theme file named by theme-file, then the colours in [theme], [theme.light], [theme.dark], [theme.todo] and [theme.category]. A TODO keyword without a colour in [theme.todo] takes its class's colour: todo-next for NEXT and STRT, todo-waiting for WAIT and HOLD, todo-cancelled for KILL and CANCELLED, and so on (see Configuration for the lists). Colours follow the system's light or dark appearance. Problems in the theme show in the Settings tab with the other problems. A change to config.toml or the theme file applies as it syncs, to open editors too. See Configuration for the colour keys.

Settings ▸ Light Theme and Dark Theme choose the built-in themes, shown as a few lines of Org in each theme's colours; with a configuration folder the choice is written to its config.toml, so the Mac uses it too. Settings ▸ App Icon chooses the home screen icon from the same thirteen as the Mac; iOS confirms the change. The icon is chosen per device.

Font
font when that family is installed on the device, otherwise the system's monospaced font. body-font, when set, is used for prose as on the Mac.
Size
font-size is the size at the default Dynamic Type setting, 13 pt by default. Text grows and shrinks with the text size chosen in the system Settings app.
Line spacing and headings
line-spacing and heading-size-step apply as on the Mac.
Text width
text-width keeps the editor's text to that many columns, centred, on an iPad or a wide window.
Caret and selection
the selection highlight takes the theme's selection colour, over block bands too; the caret and the selection handles take cursor.

The editor and the reader apply these display settings; only the editor aligns tables when a file opens. The startup settings (org-cycle-hide-*-startup, org-startup-*, org-hide-leading-stars) apply when a file opens, and a #+STARTUP keyword in the file overrides them, as on the Mac.

While markup is hidden, the line with the caret shows its markup, so you can edit it. More ▸ Show Markup, or Show or Hide Markup in Commands, switches markup in every editor and in the reader. The switch lasts until show-markup in config.toml changes; then the file's value applies.

The visibility from #+STARTUP applies first, then each heading's VISIBILITY property. As on the Mac, VISIBILITY properties apply only when #+STARTUP sets a visibility (overview, content, showall and the like).

An image line shows its image, and the link text is hidden except on the caret's line. #+ATTR_ORG: :width N sets the width in points; images are never wider than the editor. Show or Hide Inline Images in Commands, or C-c C-x C-v on a hardware keyboard, switches images in the open file. Truncate or Wrap Long Lines in Commands, or C-x x t, switches long lines. See The editor for which lines show as images.

Code in src blocks is highlighted in the theme's syntax-* colours, as on the Mac (see Code blocks).

Table columns with width cookies narrow as on the Mac: #+STARTUP: shrink narrows them when the file opens, and Shrink or Expand Table Column (C-c TAB), Shrink Table Columns with Widths and Expand Table Columns are in Commands when the caret is in a table. See Tables.

Commands

Commands (in the key bar or More) lists every command that applies at the caret, with its Emacs key. Type to narrow the list. The command runs once the list closes.

When a command asks a question, a sheet opens:

  • Text questions have a field, and a list of choices that narrows as you type. For tags, choosing a tag adds it to what you typed.
  • Date questions have a calendar as well as the field; Org's date syntax (+2d, fri, 14:00) works in the field.
  • Fast selection (TODO keywords and tags with keys) lists each option with its key. For tags, tap several and then Done; inherited tags are listed below.

Cancel answers nothing, as C-g does.

C-c ' on a block, and C-c ` on a table field, open the text in a sheet of its own; Save puts it back. A src block's code is colored as its language, as in the editor.

More ▸ Backlinks lists the links to the heading at the caret and to the file; More ▸ Daily Notes, Find Node… and Insert Node Link… work with org-roam-style notes, and the Folders tab's calendar menu opens today's, yesterday's and tomorrow's note. See Links.

Incremental Search is in Commands, and on C-s and C-r with a hardware keyboard; see The editor. auto-fill-mode works as on the Mac.

The org-timer commands are in Commands; a running timer shows above the text. See Dates and clocking.

More ▸ Attachments has the org-attach commands, Attach Photo or Video… and Take Photo…, which insert the photo's link at the caret; files shared to orgstar can be attached to an entry. Pasting an image and dropping files on the editor attach them and link them at the caret. See Outlines and Links.

More ▸ Encryption has the org-crypt commands; see Outlines. A remembered passphrase is used after Face ID, Touch ID or the device passcode.

Hardware keyboard

With a hardware keyboard, the editor uses the preset keymap sets in the folder's config.toml (emacs, mac or doom), with the folder's keymap.toml on it. The Doom preset brings Vim keys; see Keys. Bindings with ⌘ stay with iOS, so the Mac preset adds little.

  • Option works as Meta when it begins a binding (M-RET, M-<left>). Otherwise Option types characters as usual.
  • Command shortcuts are the system's.
  • Keys the keymap leaves to the text system stay with iOS. These include the editing keys C-a, C-e, C-k and similar, which iOS handles itself.
  • After a prefix such as C-c, the message line shows C-c- while it waits for the next key. An unbound sequence shows … is undefined.
  • A sequence bound to a command that can't run at the caret, or that the iOS app doesn't have, shows why, as on the Mac: the command's own message (such as Not on a heading), or Not available on iOS yet.

See Keys and commands for the Emacs bindings.

Search

Search finds:

Files
up to eight org files whose path matches what you type, ranked as Quick Open ranks them on the Mac.
Notes
headings whose title or text contains your words, and files whose text before the first heading does, including unsaved edits in the open file. Under each is the passage the words were found in, with them in bold.

Tap a result to open it in the reader. A heading result opens at that heading.

The agenda

The Agenda tab shows the agenda over all your folders, with the span and start day from the settings (10 days from 3 days ago by default). Each day lists its entries in rows: the time or a status such as Due today or 3d late on the left, the category and the keyword above the title. Days without entries are hidden, except today. Today's overdue entries are in a section of their own above today, and a line marks the current time between timed entries. Pull down to refresh.

Views (top left)
the built-in views and those in views.toml, Tags and Properties… (a match such as +work-home or TODO="WAIT"), and Search… (a phrase, or snippets such as +invoice -paid).
Folders (top right, with more than one folder)
shows or hides each folder's files in the agenda, the widgets, the watch and the badge; the shown folders' names appear under the title. A Focus can hide folders too, and mute their reminders (see Hiding folders in The agenda).
The bar at the bottom
Earlier, Filter, Today, Go to Date, the span (Day, Week, Month or the configured span, and Log Mode, which adds closed entries and clocked time) and Later.
Filter
keep or leave out tags and categories of the entries shown, or type a filter as Org's / takes it: +keep and -drop tags or categories, <0:30 for effort, /regexp/. The filter in use shows above the bar.
+ on a day's header
captures an entry scheduled on that day (see Capture).
Tap
an entry to open it in a sheet: its title, TODO state, priority, scheduled date, deadline, tags and notes. Changes use the same commands as the editor and are written to the file together on Done, or dropped on Cancel; Undo and Redo step through them. More ▸ Open in File saves and shows the entry in the reader.
Swipe left
on a TODO entry for Done, which sets the first done keyword of its sequence, or Next State; on any entry with a heading for Delete, which asks first.
Swipe right

Touch and hold
an entry for TODO State…, Reschedule, Schedule…, Deadline…, Tags…, Priority…, Clock In, Add to Calendar…, Refile…, Archive…, and Delete…. Delete… removes the heading and every line under it, after asking. Refile… lists each file and the headings in it down to level 3, as the Mac's prompt does; the entry goes to the end of the file, or under the heading, you choose. Search narrows the list by file and heading path.

Commands from the agenda change the file directly when it isn't open, and through the editor when it is. If the heading changed since the agenda was built, nothing runs.

With calendar-events on, the agenda also shows events from the Calendar app, and with agenda-reminders on, reminders from the Reminders app; see Settings below. Tap an event to edit it; an entry's Add to Calendar… adds it to a calendar. See The agenda.

See The agenda for the rows, the views and matches, and the differences from the Mac.

Widgets and the Live Activity

Widgets

orgstar has four widgets. Add them as any widget: touch and hold the Home Screen or the Lock Screen, and choose orgstar in the widget gallery.

WidgetSizesShows
TodaySmall, medium and large (Home Screen)The date, the count of open entries, and what's left of today: 3 rows (small), 4 rows (medium), or 6 rows and tomorrow's entries (large). Medium and large also count overdue entries.
Up NextRectangular, inline and circular (Lock Screen)The next entry's time or status and title (rectangular, inline), or the count of open entries today (circular, and inline when nothing is left)
HabitsSmall, medium and large (Home Screen)Each habit (STYLE: habit) in your agenda files that isn't done, with its consistency graph, as the agenda draws it: the last week (small, 3 habits), or the last three weeks and the next one (medium, 4 habits; large, 9), and how many were done today.
CaptureCircular and rectangular (Lock Screen)A button that opens the capture sheet with the template you choose when you edit the widget, or the first template.

What's left of today is today's entries and calendar events that aren't done, without timed ones that have ended (or started, when they have no end), followed by the overdue entries. The open count is today's entries not done, overdue ones included, without calendar events. The widgets use the theme's colours for the status, the keyword, the priority and the category.

Tapping a row in the medium or large Today widget opens that entry; tapping elsewhere opens the agenda. Tapping Up Next opens the next entry, or the agenda when there is none. Tapping a habit opens it.

Widgets can't read your folders, so the app writes the next seven days of the agenda (today included) for them to read: while it is open, when files, edits or settings change, when you return to the app, and every hour. Between those times the widgets move on by themselves as timed entries end and at midnight, but they show nothing new until you open orgstar. Until the app has written the agenda once, they say Open orgstar to show your agenda here. The widgets ignore the agenda's filter and show no days without entries. The Habits widget's graphs move on at midnight by themselves.

Controls

orgstar has two controls for Control Center, the Lock Screen and the Action button. Add them as any control: in Control Center, touch and hold an empty space and tap Add a Control, then choose orgstar.

Capture
opens the capture sheet. Touch and hold it while editing Control Center to choose a template; without one it uses the first.
Clock
on while a clock runs, showing its entry. Turning it off clocks out; turning it on clocks in to the entry clocked last (Clock In Last). If a clock was left running elsewhere, orgstar asks in the app how to resolve it.

The clock's Live Activity

While a clock runs, it shows on the Lock Screen and in the Dynamic Island: the heading, the time so far, and a Clock Out button. Clock Out stops the clock as Clock Out does in the app, and saves the file. Tapping the Live Activity opens the clocked entry.

The Live Activity starts when you clock in in the app and ends when the clock stops, however it stops. It needs Live Activities allowed for orgstar in the Settings app (Settings ▸ orgstar ▸ Live Activities).

Apple Watch

The watch app shows today's agenda from your iPhone, marks entries done, shows and stops the running clock, and takes dictated captures. It comes with orgstar on iPhone and installs on a paired watch as other watch apps do. It reads nothing itself: your iPhone sends it today's agenda and the clock whenever its widgets update (when files, edits or settings change while orgstar is open, and when you return to it) and whenever the clock starts or stops, and the watch keeps the last one it got. Until it has one, it says Open orgstar on your iPhone to show your agenda here.

Clocked In
the running clock's heading and its time so far, with Clock Out. Without a running clock, Clock In to heading clocks in to the entry clocked last (org-clock-in-last).
Capture
dictate or scribble text, then Done. It goes to orgstar on iPhone, which opens the capture sheet with it as %i, with the first template, as text from the share sheet does; see Capture below.
Overdue, then today
as the agenda lists them, with the time or status, the title and the keyword. Tap an open TODO entry to mark it done: it takes its sequence's first done keyword, as the agenda's Done does. The entry shows done at once; the iPhone changes the file, unless the heading changed since the agenda was sent.

What the watch asks for runs on your iPhone, which iOS wakes for it when orgstar isn't open; while the iPhone is out of reach, the requests wait and run when it is back.

Capture

Tap Capture (the pencil icon) in the Agenda or Folders tab.

  1. Choose a template. The first template is selected.
  2. Answer the template's questions (%^{…}, %^g, %^t and the like), then tap Continue. A template without questions skips this step.
  3. Edit the text. The caret is where %? was. When the text has a heading, the rows below it set the entry's State (its TODO keyword), Priority, Scheduled and Deadline dates (Today, Tomorrow, In a Week, or Pick Date…, with an optional time; Remove takes the date off) and Tags (the target file's and the workspace's, or new ones). They change the text as the editor's commands would, without logging a reschedule.
  4. Tap File.

Templates come from capture.toml in the configuration folder (see Settings below). Without one, the two default templates apply. A template with immediate-finish files as soon as its questions are answered, and one with jump-to-captured opens the captured entry. %^g offers the target file's tags as choices.

org-protocol://store-link links add the URL to the stored links that Insert Link… offers, and copy it. org-protocol://capture links opened on the device open the capture sheet with the link's template, URL, title and text. When the link names a template key that capture.toml doesn't have, the sheet starts on the first template and shows No capture template "x" with the key.

From the share sheet

orgstar appears in the share sheet of other apps for a web link or text.

  1. Share a page or text and choose orgstar.
  2. Choose a template, edit the link's title, and add text.
  3. Tap Capture.

The share extension doesn't file the entry itself. It leaves it for the app, which opens its capture sheet with the link and text the next time it becomes active. Several shared items open one after another. If the extension shows "orgstar's shared folder isn't available", the app and its extension can't share data, and Capture is disabled.

From Shortcuts

Shortcuts has a Capture to orgstar action, and Siri responds to "Capture to orgstar". The action takes:

Text
the text to capture, available to the template as %i.
Template Key
a key from capture.toml; empty uses the first template.

The action files the entry without showing the capture sheet, and saves the file at once. Questions in the template take their default answers, and %c (the clipboard) is empty, because reading the clipboard would ask for permission on every run. The action returns "Captured with" and the template's name.

See Capture for the template format.

Clocking

Clock in from the editor (More ▸ Clock In, or Clock In in Commands) or from an agenda entry's menu. While a clock runs, a bar above the tab bar shows the entry and the time so far as H:MM, updated every 30 seconds, and a Live Activity shows it on the Lock Screen and in the Dynamic Island (see Widgets and the Live Activity). Tap the bar for:

  • Clock Out
  • Cancel Clock
  • Go to Clocked Entry
  • Recent Entries
  • Clock Report

Recent Entries, in the bar and in the editor's More menu, lists the recently clocked entries; tap one to clock in to it. It also has Clock In to Recent Entry… and Go to Recent Clocked Entry…, and is disabled until you have clocked in once. Commands has Clock In to Recent Entry…, Clock In to Last Entry, Go to Recent Clocked Entry…, Mark as Default Clock Task and Resolve Open Clocks….

Clock questions open in a sheet: the task selection and the resolution keys as lists to tap, and minutes or a date and time as a field. Cancel answers nothing, as q does. Clocking in with no clock running first asks about open clocks in your folders, from the editor, an agenda entry's Clock In or a capture template with clock-in; Resolve Open Clocks… asks about every open clock. Both work as on the Mac.

The iOS app has no idle detection, so org-clock-idle-time doesn't apply. org-clock-history-length does.

Clock Report shows the time per day and heading for the files you choose. It starts with the files that contain clock lines. Turn on Limit dates to choose a range. The share button sends the report as text.

See Dates and clocking.

Reminders

With reminders on, orgstar schedules a notification before each timed agenda entry in the next week, appt-message-warning-time minutes ahead (or the entry's APPT_WARNTIME). Tap a notification to open its entry. Notifications show while the app is open too.

iOS lets an app schedule at most 64 notifications, and orgstar schedules more only while it runs. It updates them when files or settings change, when you return to the app, and every hour while it is open. The agenda's status line says how far ahead reminders are set ("Reminders are set through …"), or that notifications are off for orgstar in the system Settings app.

The app icon's badge counts the entries in the agenda's Overdue section that aren't done: past their scheduled day or their deadline, habits left out. An entry past both counts once. orgstar sets each of the next six midnights' counts ahead, so the badge stays right while the app is closed. If notifications were allowed before orgstar asked for badges, tap Show Overdue Count on Icon under Badge in orgstar's Settings; it adds Badges to orgstar's notification settings and opens them when they're still off. Turn the badge off there, under Badges.

Export

Export (in the reader's toolbar and the editor's More menu) offers HTML, Markdown, PDF, Word, Rich Text (RTF), Plain Text and iCalendar, and Copy as Rich Text. Each opens the share sheet with a file named after the org file, which you can send to another app or keep with Save to Files. The export reads the file's setup files and follows its export keywords, as the Mac's export does.

PDF export follows pdf-margin, pdf-font and pdf-page-numbers in config.toml, and Word files get heading styles and the file's images, as on the Mac. ODT, LaTeX, ASCII and PDF through LaTeX aren't available on iOS. See Export.

Code blocks and tables

C-c C-c on a source block asks whether to run it (yes, no, or always for this block), as on the Mac.

On iOS, only Emacs Lisp blocks run. orgstar evaluates them with its own Emacs Lisp interpreter, which covers a subset of the language. Other results:

  • A block in another language: "language blocks need the Mac to run."
  • Emacs Lisp the interpreter doesn't have: "This block uses Emacs Lisp that runs only in Emacs, on the Mac."

Table formulas that orgstar computes itself work on iOS. A table whose formulas need Emacs reports "This table needs Emacs, which runs on the Mac", with the reason, and isn't changed.

Tangling (C-c C-v t, in Commands) works on iOS and writes the tangled files next to the org file, or where :tangle says.

See Code blocks and Tables.

Conflicts and versions

When a file changes on disk while you have unsaved edits, orgstar merges the change into your edits. When the changes overlap, the conflict sheet opens. It shows the difference (lines marked - are on disk, + in your version) and offers:

Keep Mine
write your version over the disk version.
Use Disk Version
replace your edits with the disk version.
Merge with Markers
put both versions in the editor, with conflicting lines between <<<<<<< and >>>>>>> markers, to fix and save.
Later
decide later. The Conflict button in the toolbar opens the sheet again. Nothing is saved until you decide.

The version you don't keep goes to the recovery folder.

More ▸ Sync Conflict Copies lists Syncthing's conflict copies of the file (name.sync-conflict-…), each compared with the file, with Keep File, Merge and Use Copy. The copy goes to the recovery folder and is removed. When a file with conflict copies opens in the editor, a message says how many there are.

More ▸ Recovered Versions lists the versions of the file kept in the recovery folder, newest first, each compared with the editor's text. Restore puts a version's text in the editor as an edit you can undo.

See Working alongside Emacs and other tools for how merging and recovery work.

Settings

The iOS app reads its settings from a configuration folder: a folder holding config.toml and capture.toml, such as a copy of the Mac's ~/.config/orgstar synced through iCloud Drive or another app.

  1. Open the Settings tab.
  2. Tap Choose Folder… and choose the folder. If it has no config.toml, orgstar writes one with every setting at its default, each with a comment, as the Mac does.

Changes to the files apply as they sync, and again each time you return to the app. Problems in the files show in red under the folder. "No config.toml in folder; the defaults apply" means the folder has no config.toml, for example because it was removed after you chose the folder.

Edit config.toml opens the folder's config.toml as plain text, with smart quotes and dashes off. Save, or going back, writes it and applies it at once; problems show in red below the text.

Stop Using This Folder returns every setting to its default.

Import from Emacs reads an Emacs or Doom configuration folder, such as a synced ~/.config/doom or ~/.emacs.d, as the Mac's import does (see Configuration):

  1. Tap Import from Emacs, then Choose Folder…, and choose the folder holding init.el, config.el or config.org.
  2. The screen lists the settings, capture templates, key bindings, structure templates and agenda views it found, each with the line it came from, all selected. Clear what you don't want.
  3. Tap Import. The screen then summarizes what was imported and any problems.

With a configuration folder, settings and structure templates are written to its config.toml, and capture templates, key bindings and agenda views to its capture.toml, keymap.toml and views.toml, so the Mac reads them too. Without one, settings are kept on the device. Folders from org-agenda-files name the Mac's paths and aren't offered.

The Agenda, TODO Dependencies, Calendar and Reminders sections are the only places the app changes a setting itself, besides Import from Emacs:

Show days without entries
turns org-agenda-show-all-dates on or off.
Habits only today
turns org-habit-show-habits-only-for-today on or off.
Exclude archived tasks
turns agenda-exclude-archives on or off: the agenda leaves out the files your agenda files archive to.
Blocked entries
Dimmed, Hidden or Shown as usual (org-agenda-dim-blocked-tasks).
TODO Dependencies
Not done before TODO children (org-enforce-todo-dependencies) and Not done with unchecked boxes (org-enforce-todo-checkbox-dependencies).
Show Calendar Events
turns on calendar-events, and asks for access to your calendars. iOS asks for full access, as Calendar has no read-only level; orgstar changes a calendar only when you edit an event or add an entry. While access is missing the section shows Allow Access to Calendars…; if you declined, allow it in the Settings app under Privacy & Security ▸ Calendars.
The calendars
tap one to show or hide its events (calendar-event-calendars). With every calendar checked the setting is empty, so calendars added later show too.
Show Reminders
turns on agenda-reminders and asks for access to your reminders; Allow Access to Reminders… shows while it is missing. Tap a list to show or hide its reminders (agenda-reminder-lists).

These write config.toml in the configuration folder, as the Mac's Settings window does, so the Mac sees the change too. Without a configuration folder they are kept on the device.

The In use section shows the TODO keywords, the agenda span and start (for example 10 days, starting today), the reminder lead time, the capture template keys, the light and dark themes, and the theme file's name when there is one, and the font with its size. When font names a family that isn't installed on the device, Font shows the system's font with a note, as System monospaced, 13 pt (JetBrains Mono isn't installed).

About orgstar, at the bottom, shows the version and links to the manual, the release notes, the website, the issue tracker (which needs a gitbay account), support by email at help@krz.sh with the version and device filled in, the App Store review page, the source code, the license, third-party notices and the privacy policy.

Spotlight and Quick Look

orgstar adds the org files in your folders to Spotlight with their title (#+TITLE, else the file name), author, description, tags, headings and text. A file is indexed again when it changes. Tap a Spotlight result to open the file in orgstar's reader.

Quick Look in the Files app shows org files as the HTML export renders them.

What the Mac has that iOS doesn't

  • Running code blocks in languages other than Emacs Lisp, Emacs Lisp beyond orgstar's interpreter, and tables that need Emacs.
  • ODT, LaTeX, ASCII and LaTeX-made PDF export, and publishing.
  • Idle detection while a clock runs.
  • Import from Emacs of agenda folders.
  • The Columns inspector, the buffer list and tab bar, and resizing panes by dragging their divider. The board and column view are there (see The agenda and Outlines).
  • The global capture hotkey and the Settings window.
  • Explicit saving.

Commands the iOS app can't carry out show a message instead, such as "Not available on iOS yet" or "Command isn't available on iPhone and iPad." Only tables that need Emacs say that Emacs is needed. Commands that only appear on the Mac aren't listed in Commands. Refile… in Commands (or C-c C-w with a hardware keyboard) refiles the entry at the caret, choosing the target as the agenda's Refile… does.
