# orgstar review, 2026-10-13

Scope: features, as seen by three users: an Emacs org-mode user, a writer or note-taker who has never used Emacs, and a general productivity user. IDE features are out of scope. The review covers the manual (all fifteen chapters), the design doc, the previous review, the open and closed issues, and the Swift sources where the manual made a claim worth checking. The build and the full test suite pass at 117a5b0 (`swift build`, `swift test`, both exit 0).

Facts about the codebase, for calibration:

## 1. Verdict

orgstar is an Org implementation first and an app second. Where Org has a behaviour, orgstar reproduces it, checks it against Emacs, and refuses with a message rather than guessing. That discipline makes it unusually trustworthy as a second editor on a folder that Emacs, Syncthing and iCloud also write to. The save path (read, merge, atomic replace, read back, recovery copies) is better than Emacs's own.

Judged as an app for org-mode users it is strong and nearly complete for daily use. Judged as a writing platform it is weak: nearly every comfort a prose editor offers is absent, and several defaults work against prose. Judged as a productivity app it has more surface than most task managers (agenda, kanban, habits, clocking, widgets, watch, Shortcuts, Calendar and Reminders overlays) but every one of those surfaces assumes the user already knows Org's vocabulary and is willing to edit TOML files.

The single largest gap is not a feature. It is that the product is documented and configured in Org's terms and has no path that teaches those terms. A newcomer gets an empty window that says "Add a folder of org files", Emacs keys by default, and a 680 kB manual organised by Org variable name.

## 2. As an app for org-mode users

### What is good

- **Fidelity.** Byte-exact round trips, CRLF and BOM preserved, incremental reparse checked against a full parse, commands checked against `emacs --batch` on pinned Org 9.8.7. Babel cache hashes match Emacs's, so `#+RESULTS[hash]` survives a round trip between the two.
- **Multi-writer safety.** Three-way line merge on external change, conflict sheet with Keep Mine / Use Disk / Merge with Markers / Decide Later, Syncthing conflict-copy resolver, 20 recovery versions per file, running clocks followed from `CLOCK:` lines edited elsewhere.
- **Agenda depth.** Day, week, month, configured span, `org-agenda-sorting-strategy` with all of Org's keys, filters (`/`, `\`, `<`, `=`, `_`), log mode, bulk actions, block agendas and saved views in `views.toml`, stuck projects, habits with the consistency graph, diary sexps with a Lisp subset, deadline warning and scheduled delay cookies, `org-agenda-todo-ignore-*`, time grid and now line.
- **Capture.** Every `org-capture` target except `function`, every escape except `%(…)` beyond the Lisp subset, datetree with grouped tree types, `org-protocol` in both URL forms so existing bookmarklets work, a global hotkey, Shortcuts, the share sheet.
- **Clocking.** Resolution of open clocks with Org's full key set, idle detection on the Mac, rounding, `CLOCK_INTO_DRAWER`, clocktable dynamic block with most of its parameters, effort overrun notification, menu-bar clock, Live Activity on iPhone.
- **Tables.** A Calc subset with Org's exact display rules, durations, `remote()` across indexed files, formula editor, iterate, `<N>` shrink, table.el tables edited in place, `#+PLOT` through gnuplot or Swift Charts, CSV import and export on both platforms.
- **Babel.** Shells, Python, Ruby, Node, R, awk, dot, plantuml, mermaid, and compiled C, C++, D, Java, Fortran and Clojure; sessions for shells, Python, Ruby, Node and R; noweb with all modes; `#+CALL` and inline `src_`; tangling with `:comments` and about 60 comment syntaxes; a hash-keyed trust store.
- **The rest of Org.** org-crypt (symmetric, gpg-compatible), org-attach, column view with editing, footnote commands, sparse trees, narrowing, structure templates, fast TODO and tag selection, TODO dependencies, `#+SETUPFILE`, `#+INCLUDE`, macros, citations (oc-basic), iCalendar export, publishing projects, an org-roam subset with dailies and backlinks.
- **Doom.** A real modal engine: operators, motions, text objects including evil-org's, registers, macros, marks, jump list, surround, numbers, `.` repeat, ex commands, `SPC` leader.

### Where an Emacs user will stumble

Ordered by how often it bites.

1. **No prefix argument.** `C-u` does not exist. Every `C-u` form is a separate command, several of them with no key (Remove Schedule, Remove Deadline, Iterate Table Formulas, the `org-timer` forms). Muscle memory such as `C-u C-c C-s` fails silently or does the un-prefixed thing.
2. **No kill ring.** `C-k` and `C-y` use the macOS kill buffer; `C-w` and `M-w` use the clipboard; `M-y` does not exist. Mixing them loses text.
3. **Doom defaults, not Org defaults.** `org-todo-keywords` is the Doom set, so `C-c C-t` opens fast selection instead of cycling TODO/DONE. `org-insert-heading-respect-content` is true, so `M-RET` inserts after the subtree. `fill-column` is 80, alphabetical lists are on, `org-agenda-show-all-dates` is off. All are documented in chapter 15 and changeable, but a plain-Emacs user's first session on a shared file will differ from Emacs in these places.
4. **Logging is off and hidden.** `org-log-done`, `org-log-into-drawer`, `org-log-reschedule` and `org-log-redeadline` are nil by default and exist only in `config.toml`. There is no `org-add-note` (`C-c C-z`). Keyword and tag-inheritance changes need an app restart.
5. **Emacs fallbacks run `-Q`.** Elisp blocks, Lisp table formulas, and PDF, LaTeX, ODT and ASCII export run without the user's init file, packages, `org-latex-classes` or export filters. For most people the point of LaTeX export is their own preamble, so the fallback covers less than it appears to.
6. **Undo.** Linear, cleared on every external reload or merge, not persisted across quit. Emacs's undo tree and `undo-fu` users will notice the clearing most, since Syncthing makes reloads common.
7. **Agenda is a window, not a buffer.** No `org-agenda` dispatcher, agenda keys are fixed and not in `keymap.toml`, `org-agenda-prefix-format` mostly ignored because rows have their own layout.
8. **keymap.toml semantics.** A binding without `mode` never runs under Doom, and one with `mode` never runs under Emacs or Mac, so one file cannot serve both presets. `"none"` cannot unbind in a single context.
9. **Babel refusals.** `:post` for every language; `:session` for Emacs Lisp; `:var` indexing and cross-file `:var`; noweb references that run a block; Perl, Lua, Julia, SQL, Haskell, Rust, Go, Swift, Octave, gnuplot, ditaa and LaTeX blocks do not run at all (several of these are highlighted, which suggests they would). Compiler output is dropped, so a C compile error is invisible.
10. **Config does not reach iOS by itself.** `config.toml` lives in `~/.config/orgstar`, outside anything iOS can see. The manual says to sync a copy "through iCloud Drive or another app" and leaves the mechanism to the user. `default-theme.toml` is rewritten on every launch in the same folder, which the manual says to keep out of dotfiles.
11. **Smaller.** Stored links die at quit (as in Emacs, but with no persistence option). Regexp links are documented as both supported (09-links.org:63) and unsupported (09-links.org:73). `info:` and `help:` links do nothing. `<s TAB` does not expand; only Complete at Point does. Archived subtrees open on `TAB`. No `org-toggle-checkbox` on headings or regions. Publishing ignores `:with-toc`, `:html-head` and the prep and completion functions.

### Net

For someone whose Emacs use is org-only, orgstar can replace it today on the Mac, provided they import or rewrite their config and accept the eleven items above. For someone whose Org workflow leans on Lisp (custom agenda skip functions, `%(…)` captures, own export filters, ob-* packages), it is a companion, not a replacement. The manual's chapter 15 says this honestly.

## 3. As a writing platform

This is the weakest of the three lenses. The code is an org editor with Emacs's display model; it is not shaped for prose, and the defaults point the other way.

### Present and good for writers

- Hidden markup with reveal on the caret's line, emphasis drawn as bold and italic, pretty entities and sub/superscripts, link brackets hidden. This is the closest thing to a WYSIWYG mode and it is well done.
- Inline images with `#+ATTR_ORG: :width`, paste and drop of images into attachments, remote images with a cache.
- LaTeX fragments typeset natively (SwiftMath), no TeX install, works on iOS.
- Spell check that skips code, links, tags, drawers, timestamps and blocks (`SpellCheck.swift`, mirrors spell-fu). On the Mac only.
- Fill and auto-fill ported from Emacs; soft wrap with adaptive indent under bullets.
- VoiceOver reads the text as shown, not as stored (`Accessibility.swift`). Rare in a custom text view.
- Entry-level encryption interoperable with gpg and Emacs, unlocked with Touch ID or Face ID.
- Dailies, datetree capture and a reader mode on iOS.
- Copy as Rich Text, and native HTML, Markdown, PDF, Word, RTF and plain-text export without Emacs.

### Absent or working against prose

Typography and layout:

- The font picker lists only fixed-pitch families (`OrgstarApp.swift:614`); a proportional font requires editing `config.toml`, and indent and alignment are computed from the width of `0`, so proportional text misaligns tables and tags. There is no variable-pitch body with fixed-pitch tables and code, which is what Emacs users get from `mixed-pitch` and what every prose app does by default.
- No line-width limit or margin. Text runs edge to edge in a wide window. iOS has a fixed 8 pt inset.
- Line numbers on by default, with a gutter.
- One built-in theme. Colours are editable only in TOML. No serif or prose preset.
- No paragraph spacing, first-line indent, or per-role fonts.

Focus and flow:

- No typewriter scrolling, no sentence or paragraph focus, no distraction-free mode beyond macOS full screen and hiding panes. Narrowing to a subtree is the nearest thing.
- No reader or preview mode on the Mac; only iOS has one.
- Smart quotes, smart dashes, autocorrect and text replacement are hard-set off on both platforms, with no setting to turn them on (`OrgEditor.swift:198`, `MobileEditor.swift:197`).
- Spell check is off by default, toggled from the palette only (no menu item, no Mac key), and on iOS it marks code and links because the skip list is not applied there.
- There is no bold, italic or code command and no `⌘B`/`⌘I`. Org's own `org-emphasize` (`C-c C-x C-f`) is missing. The iOS key bar has structure buttons (Promote, Demote, TODO, Schedule) and no formatting buttons.

Statistics:

- A whole-file word count in the Mac modeline, counting property drawers, keywords and code. No character count, reading time, per-section count, goals, or any count on iOS.

Search and linking:

- Cross-file search is heading-granular FTS over title and body, word-prefix only, 50 results, no snippets or match highlighting, no regex or case options, no replace across files. The body text before a file's first heading is not indexed at all (`FileRecord.swift:172-213` builds one FTS row per heading; the zeroth section is read only for `#+TITLE`). A flat note file with no headings is therefore unsearchable except by file name.
- Backlinks list the linking heading and file, with no context line. No unlinked references, no graph, no aliases, and Find Node and Insert Node Link do not create a node from a title that is not found (chapter 15 confirms this).
- `[[` completion offers headings of the current file only.

Export quality for writers:

- PDF is the HTML export printed through WebKit: fixed 50 pt margins, 11 pt body, no page numbers, headers or footers, no font or margin control, light colours only, footnotes at the end rather than per page, MathJax fetched from a CDN so math needs network. Typeset output requires Emacs plus TeX on the Mac.
- Word output is hand-written OOXML with no `styles.xml`, so headings are direct formatting rather than Word heading styles (no navigation pane, no TOC field), and images are omitted (`DocxWriter.swift`). Fonts are fixed to Helvetica Neue and Menlo.
- RTF and plain text on iOS lose tables.
- Citations: oc-basic only. CSL and biblatex citations are left as written. No citation picker, no Zotero.
- No Markdown import, and the iOS app lists `.org` files only.

History:

- Recovery versions are kept only when a save displaces someone else's version or a conflict is resolved. Ordinary editing has no snapshot history. Git integration is a branch name in the modeline. A writer who deletes a paragraph and saves (which happens automatically one second later) has only linear undo, which is cleared on the next external reload.

### Net

A writer who already lives in Org and wants their files on an iPhone will find this workable and will appreciate the hidden markup and the reader mode. A writer choosing between this and Ulysses, iA Writer, Bear or Obsidian will not choose this, and the gap is wide enough that closing it is a product decision rather than a feature list. The cheapest changes with the largest effect are: a proportional body font with fixed-pitch tables and code, a readable line width, line numbers off by default, spell check in the View menu and on by default, and indexing the preamble.

## 4. As a productivity app

### Present and good

- The agenda is the most complete Org agenda outside Emacs, and the row design (status column, category, badges, habit graph, overdue group, now line) is clearer than Emacs's text rows.
- Kanban board with drag between keyword columns, and a table mode with property columns.
- Habits with org-habit's colouring on Mac, iOS and widgets.
- Clocking with a menu-bar item, Live Activity, Control Center controls and a watch complication.
- Capture from anywhere: global hotkey, share sheet, Shortcuts and Siri, org-protocol bookmarklets, widgets, the watch, the `+` on an agenda day that schedules the entry on that day.
- Calendar events and Reminders shown in the agenda, Add to Calendar from an entry, Edit Event in place.
- Notifications before timed entries with `APPT_WARNTIME`, an overdue badge, iCalendar export for subscribing from any calendar.
- iOS swipe actions (Done, Next State, Tomorrow, Next Week, Pick Date) and a long-press menu with the whole set of entry commands.
- Widgets on Mac desktop and iOS Home and Lock Screen, a watch app.

### Where a productivity user will stumble

1. **Everything is Org.** TODO keyword sets, capture templates, agenda views, refile targets and archive locations are TOML strings in Org's syntax. Three of the five config files (`keymap.toml`, `capture.toml`, `views.toml`) have no editor in the app on either platform. The default templates assume `todo.org` and `notes.org` exist.
2. **Completion timestamps are off.** With `org-log-done` nil and absent from the Settings window, a default install records no `CLOSED` time and no state history, so "when did I finish this" has no answer until the user finds a TOML key.
3. **Keys on the Mac preset.** The Mac preset has no keys for Agenda, Capture, single-format export, Remove Schedule, Column View or Mark Subtree, and Org commands sit on `⌃⌘` and `⌃⌥⌘` chords. Speed keys are off with no Settings control. The default preset is Emacs.
4. **The date prompt ignores words it does not know.** `tomorrow` returns the default date silently (06-dates-and-clocking.org:100). `fri`, `+2d` and `w42` work. This is Org's behaviour, and it is a trap for anyone who has used any other task app.
5. **Widgets, watch and reminders go stale.** Widget data is written only while the app runs; notifications are capped at 64 and a week ahead; the watch shows whatever the iPhone last sent. The manual explains all three. A user who does not open the app for a week gets no reminders in week two.
6. **Capture behaves differently by entry point.** The share sheet and watch queue the entry until the app is next active; Shortcuts files at once but with default answers and an empty clipboard; the watch always uses the first template.
7. **Reminders are read-only.** Completing an Org entry does not complete the Reminders item and vice versa.
8. **Files outside the added folders** open and edit but are silently absent from the agenda, search, backlinks and ID resolution, and are not watched for external changes.
9. **iOS is build-from-source.** The README links to `apps.apple.com/app/idXXXXXXXXXX` twice (README.org:11, :58); install.org says to open the Xcode project, choose a team and rename the bundle identifiers and App Group; CONTRIBUTING.org:8 says Simulator builds only; issue 8 (device signing and TestFlight) is open. A general user cannot get the iOS app.
10. **No onboarding.** Both apps start at an empty state ("Add a folder of org files"), with no sample file, no suggested folder, no preset chooser, and no explanation of what an org file is. On iOS the Agenda tab is the default, and its empty state has no button; the user must find the Folders tab.
11. **Release notes.** Every appcast item from 0.3.0 to 0.4.2 carries the same text, "Universal (Apple silicon and Intel), macOS 26 or later. Notarized." A Sparkle update dialog therefore never says what changed.

### Net

As a task manager for someone who already uses Org, it is better than Emacs on a phone and competitive with it on a Mac. As a task manager for anyone else, the vocabulary barrier is the product. The feature set would support a guided path (pick a folder, pick Mac keys, create `inbox.org`, turn on completion logging, show the agenda) that the app does not have.

## 5. Cross-cutting observations

- **Discoverability.** A large share of commands are palette-only on the Mac: Recovery Versions, Resolve Sync Conflicts, Revert to File on Disk, spell check, Close Other Buffers, Encrypt Entry, Board on the Mac preset, Import and Export Table, and the single-format exports. The palette (`⇧⌘P`) and the which-key panel after 0.6 s carry most of the discoverability load.
- **Settings surface.** Five tabs cover about a third of the settings; the rest is `config.toml`. The split is sensible for Org users and hostile to everyone else. iOS has even less in its GUI (Agenda, dependencies, Calendar, Reminders, Import from Emacs) and a raw TOML editor for the rest.
- **Two visible defaults that cut against both newcomers and Emacs users at once:** Doom's TODO keywords and Doom's `M-RET` behaviour. Each is a surprise to plain-Emacs users and meaningless to newcomers. Org's own defaults would serve both better; Doom users get theirs from Import from Emacs.
- **Localisation.** English and German strings exist (548), but day and month names in timestamps and the clocktable labels are English only, and the manual is English only.
- **Accessibility.** The Mac editor's VoiceOver mapping is careful. The iOS editor is a stock `UITextView` with no comparable layer. Both VoiceOver passes are still open issues (3 and 4), as they were in the October 5 review.
- **Quality discipline.** The oracle tests, the conformance goldens, the fault-injection save tests and the file-size check are all still in place. Every defect from the October 5 review's table is fixed or tracked. The refusal-with-a-message pattern holds across Babel, tables, capture and links.

## 7. Priorities

Ordered by effect on the three audiences, cheapest first within a tier.

Tier 0, documentation and distribution:

1. Fix the twelve defects in section 6. Most are one-line edits.
2. Write real release notes into the appcast per version.
3. Either remove the App Store links from the README or ship TestFlight (issue 8) and then the store.

Tier 1, defaults and discoverability (helps all three audiences, little code):

1. Org's own TODO keywords and `org-insert-heading-respect-content` nil as defaults; Import from Emacs already restores Doom's.
2. `org-log-done`, `org-log-into-drawer`, `org-use-speed-commands` and `spell-check` in the Settings window.
3. Menu items for Recovery Versions, Resolve Sync Conflicts, Revert to File on Disk and Check Spelling While Typing.
4. Mac preset keys for Agenda, Capture and Remove Schedule / Remove Deadline.
5. A first-run sheet: choose a folder (offer to create one in iCloud Drive), choose a key preset, create `inbox.org`. On iOS, make Folders the default tab until a folder exists.
6. Accept `today`, `tomorrow`, `yesterday` and `next week` in the date prompt, as orgstar's property matcher already does for `"<tomorrow>"`.

Tier 2, writing (the lens with the most room):

1. Proportional body font with fixed-pitch spans for tables, code, verbatim and the heading tag column; compute org-indent and tag alignment in fixed-pitch units. This is the one change that moves orgstar from "Emacs look" to "prose editor look".
2. A readable line width setting, line numbers off by default in org files.
3. Index the zeroth section's body text; add snippets and match highlighting to Search Notes.
4. `org-emphasize` with `⌘B`, `⌘I`, `⌘K`-style keys in the Mac preset and buttons on the iOS key bar.
5. Spell-check skip list applied on iOS; a character count and reading time next to the word count; the word count on iOS.
6. Word export with `styles.xml` and images; PDF page numbers and a margin and font setting.
7. Create a node from a title in Find Node, and context lines in the backlinks pane.
8. Snapshot history for ordinary edits (a recovery copy on each save that changes more than N lines, or per hour), surfaced in the existing Recovery Versions UI.

Tier 3, Org parity still owed:

1. A prefix-argument mechanism for the Emacs and Doom presets, even if only numeric and `C-u` once, so `C-u C-c C-s` and `C-u C-c =` work.
2. A kill ring with `M-y`.
3. `org-add-note`.
4. `:post` and cross-file `:var` in Babel; Perl, Lua, SQL and Julia as generic runners; compiler output kept on failure.
5. Config sync to iOS: let the app read `config.toml` from a folder the user adds, or write it into the first folder as `.orgstar/config.toml`.
6. The two VoiceOver passes and the M1 Air gate run (issues 2, 3, 4), which have now been open through two reviews.
