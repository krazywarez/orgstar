#+TITLE: Keys and commands
#+DESCRIPTION: The three key presets, prefix keys and key hints, the echo area, the command palette, Option as Meta, keymap.toml, Vim editing in the Doom preset, and every binding.
#+LEDE: Every action in Orgstar is a named command; a keymap preset decides which keys run which commands, and keymap.toml lets you change that.

* Commands and keymaps

Each action has a command id such as =org.todo.cycle= and a title such as /Cycle TODO State/. Keys, the Org menu, the command palette and the iOS key bar all run commands by id. A keymap maps key sequences to command ids. Orgstar ships three keymaps, called presets, and reads your own bindings from =keymap.toml= on top of the one you choose.

Ids starting with =org.= are Org commands and run only in Org files. Ids starting with =edit.= are text-system actions (movement, killing, find). Ids starting with =app.= are carried out by the app: saving, buffers, windows, export. =editor.= ids change how the editor behaves. The [[*Key reference][key reference]] at the end of this chapter lists every bound command with its keys in each preset.

* Choosing a preset

Choose a preset in Settings ▸ General ▸ Keys, or with =keymap= in the =[orgstar]= table of =config.toml= (see [[file:13-configuration.org][Configuration]]). The change applies at once.

| Preset | =config.toml= value | What it is |
|-+-+-|
| Emacs | ="emacs"= | Emacs and Org keys: =C-f=, =C-k=, =C-x C-s=, =C-c C-t=, =M-RET=, =M-<left>=. The default. |
| Mac | ="mac"= | Standard macOS text keys stay as they are. Org commands use Control-Command chords (=⌃⌘T=, =⌃⌘←=), which macOS text editing leaves free. |
| Doom (Vim keys) | ="doom"= | Modal editing as in Doom Emacs with evil and evil-org: normal, insert and visual states, the =SPC= leader and =SPC m= local leader, plus the Emacs preset's Org keys in every state. |

The Mac preset binds fewer commands than the others. =⌃⌘X= is its =C-c C-c=, =⌘K= inserts a link and =⇧⌘E= opens the export sheet; the [[*Key reference][key reference]] lists the rest. It has no keys for agenda, capture or the single export formats. Run those from the Org menu, from the command palette (=⇧⌘P=), from a menu shortcut (Agenda =⇧⌘A=, Capture =⇧⌘N=), or bind them yourself in =keymap.toml=.

In the Emacs and Mac presets, and in Doom's insert state, macOS's own text keys keep working where the preset does not bind the key: =⌥←=, =⌘←=, =⇧= with arrows to select, and the Control keys the macOS text system provides (=⌃A=, =⌃E=, =⌃K= and so on). Menu shortcuts such as =⌘S= and =⌘F= work in every preset; see [[*Menu shortcuts][Menu shortcuts]].

* Option as Meta

Emacs notation writes Meta as =M-=. On a Mac keyboard Meta is the Option key, but Option also types characters such as =é= and =ø=. Settings ▸ General ▸ Option as Meta picks which Option keys act as Meta:

| Choice | =config.toml= (=option-as-meta= in =[orgstar]=) | Effect |
|-+-+-|
| Left Option | ="left"= | The left Option key is Meta; the right one types characters. The default. |
| Right Option | ="right"= | The right Option key is Meta. |
| Both | ="both"= | Both are Meta; Option no longer types special characters in the editor. |
| Neither | ="none"= | Option always types characters. Plain =M-= keys such as =M-f= cannot be typed; chords that also use Control or Command still work. |

Option pressed together with Control or Command always counts as Meta, whatever this setting says, so chords such as =C-M-i= (=⌃⌥I=) and the Mac preset's =⌃⌥⌘←= always work.

* How keys reach commands

** Contexts

One key can run different commands depending on where the caret is. In the Emacs preset =M-<right>= demotes a heading, indents a list item and moves a table column right. Each binding can name a context, and Orgstar tries the bindings for a key from the highest priority down. The first one whose context holds and whose command can run at the caret wins.

| Context | Holds when |
|-+-|
| =heading= | The caret is on a heading line. |
| =item= | The caret is inside a list item. |
| =table= | The caret is inside a table. |
| =tblfm= | The caret is on a =#+TBLFM:= line. |
| =timestamp= | The caret is on a timestamp. |
| =property= | The caret is on a property line in a property drawer. |
| =src= | The caret is inside a src block. |
| =dblock= | The caret is on the =#+BEGIN:= line of a dynamic block. |
| =fold-line= | The caret is on the first or last line of a drawer or block, where =TAB= folds it. |
| =region= | Text is selected. |
| =speed= | Speed keys are on, nothing is selected, and the caret is at the very start of a heading line. See [[*Speed keys][Speed keys]]. |

When no binding for a key applies:

- In the Emacs and Mac presets, a single key goes to the text system and does what it normally does. =TAB= outside a heading, drawer edge or table types a tab; =S-<right>= on plain text extends the selection.
- A key sequence of two or more keys runs its highest-priority command anyway, so you see that command's message (for example "Not on a heading").
- In the Doom preset the keys go on to the Vim engine (see [[*Vim editing (Doom preset)][Vim editing]]).

In a file that is not an Org file, =org.= commands never apply, so their keys fall through as above.

** Prefix keys and key hints

A prefix is a key that starts longer sequences, such as =C-c=, =C-c C-x=, =C-x n= or, in the Doom preset, =SPC= and =SPC m=. After a prefix, Orgstar waits for the next key and shows the keys typed so far in the echo area, followed by a dash: =C-c C-x-=.

If you pause on a prefix for 0.6 seconds, a panel of key hints opens above the echo area. It lists each key that can follow, sorted by key, with the title of the command it runs, or =+prefix= when it leads to a longer sequence. This is Orgstar's version of =which-key=. The hints follow the current keymap, including your =keymap.toml=, and in the Doom preset the current evil state. When a key has several contexts (=C-c C-c= is the common case), the hint shows the command that would run at the caret; where none of them applies, it shows the highest-priority one.

=C-g= during a prefix cancels it; in the Emacs and Mac presets the echo area shows =Quit=. A sequence that nothing binds shows, for example, =C-c z is undefined= and does nothing. In the Doom preset this holds for sequences that start with =SPC= or with a Control or Meta key; see [[*How keys are handled][How keys are handled]] for the others.

A key bound by itself cannot also be a prefix. When a keymap binds both =C-c= and =C-c C-t=, =C-c= always waits for the next key, so the binding for =C-c= alone never runs.

* The echo area

The echo area is the line at the bottom of the window, below the modeline. It shows, in order of priority:

- A question a command is asking, with a text field: a refile target, a date, a property value, a sparse-tree match, a Vim search or ex command. =Return= answers, =Esc= cancels. When the question has choices, they are listed above the field and filtered as you type with fuzzy matching; =Tab= completes the best match. Date questions show a calendar, and =S-<left>=, =S-<right>=, =S-<up>= and =S-<down>= move the date by a day or a week, as in =org-read-date=.
- Fast selection for TODO keywords and tags when the file defines keys for them (see [[file:05-todos-and-tags.org][TODOs and tags]]).
- The pending prefix, such as =C-c C-x-=.
- The last message from a command or from the keymap, for four seconds.

In the Doom preset the modeline shows the evil state as a tag: =NORMAL=, =INSERT=, =VISUAL=, =V-LINE= or =V-BLOCK=. See [[file:02-the-editor.org][The editor]] for the rest of the modeline.

* The command palette

The palette lists every command by title with its keys in the current keymap. Open it with:

- =⇧⌘P= or File ▸ Command Palette… in every preset,
- =M-x= in the Emacs and Doom presets (=execute-extended-command=),
- =SPC := in Doom normal state.

Type part of a title; matching is fuzzy and the best matches come first. =Return= runs the top match, a click runs any row, and =Esc= closes the palette. Each row shows up to two key sequences; in the Doom preset these are normal-state keys first, then insert-state keys.

The palette leaves out text-system movement and editing commands (Forward Character, Kill Line, Set Mark and the like), which only make sense from keys. Every other command is in it, including the ones no preset binds, such as Show or Hide Backlinks, Import Table from File…, Recovery Versions… and Delete Property…. Commands that cannot run at the caret show a message instead.

The Org menu in the menu bar lists every =org.= command with its keys in the current keymap, and is a way to find a key without the palette. Its Clock submenu lists the clock commands the same way, followed by the recently clocked entries.

* Speed keys

With =org-use-speed-commands= set to =true= in =config.toml=, single letters typed at the very start of a heading line, before the stars, run commands instead of inserting text (=org-speed-commands=). Anywhere else the letters type as usual. The setting is off by default and has no checkbox in Settings.

Speed keys work in the Emacs and Mac presets, and in the Doom preset in insert state. The full list is in the [[*Speed keys reference][speed keys reference]].

* Customizing keys: keymap.toml

Your own bindings go in =keymap.toml= in the configuration folder: =$XDG_CONFIG_HOME/orgstar/keymap.toml= when =XDG_CONFIG_HOME= is set, otherwise =~/.config/orgstar/keymap.toml=. Settings ▸ General shows the path under the Keys picker. The file does not exist until you create it. If you used an earlier version that kept it in =~/Library/Application Support/Orgstar/=, that copy is read, and reloaded when you save it, until one exists in the configuration folder.

The bindings in the file are layered on top of the chosen preset. They apply to whichever preset is chosen, so a file written for the Emacs preset does nothing useful under Doom unless its bindings name a =mode=.

** Format

The file is a list of =[[bind]]= tables, one per binding:

#+BEGIN_SRC toml
# C-c t cycles the TODO keyword.
[[bind]]
keys = "C-c t"
command = "org.todo.cycle"
#+END_SRC

| Field | Required | Meaning |
|-+-+-|
| =keys= | yes | The key sequence, in Emacs notation, chords separated by spaces. |
| =command= | yes | A command id, or ="none"= to unbind. |
| =when= | no | A context from the table in [[*Contexts][Contexts]]. Without it the binding holds everywhere. |
| =mode= | no | An evil state for the Doom preset: ="normal"=, ="insert"= or ="visual"=. |

The [[*Key reference][key reference]] gives each command's id after its title. Commands no preset binds are listed under [[*Unbound commands][Unbound commands]]. A binding whose command id Orgstar does not know is skipped and reported when the file loads (see [[*Reloading and errors][Reloading and errors]]).

Orgstar reads a subset of TOML: =[[bind]]= headers, =key = value= lines, basic ="..."= and literal ='...'= strings, =true= and =false=, integers, and =#= comments. Arrays, inline tables and multi-line strings are not supported.

** Key notation

| Notation | Key |
|-+-|
| =C-= | Control (=⌃=) |
| =M-= | Meta: Option (=⌥=), as set in [[*Option as Meta][Option as Meta]] |
| =S-= | Shift (=⇧=) |
| =s-= | Command (=⌘=) |
| =a=, =%=, =/= | A single character |
| =TAB=, =RET=, =SPC=, =ESC=, =DEL= | Tab, Return, Space, Escape, Delete (backspace) |
| =<left>=, =<right>=, =<up>=, =<down>= | Arrow keys |
| =<home>=, =<end>=, =<prior>=, =<next>= | Home, End, Page Up, Page Down |
| =<delete>= | Forward delete (=⌦=) |
| =<f1>= to =<f12>= | Function keys |

Modifiers combine: =C-M-s-<left>= is =⌃⌥⌘←=. =<tab>=, =<return>=, =<escape>= and =<backspace>= are accepted as other names for =TAB=, =RET=, =ESC= and =DEL=, and =<backtab>= for =S-TAB=.

Shift with a letter is written as the capital letter: =S-a= and =A= are the same key, and so are =C-S-h= and =C-H=. With other keys Shift stays a modifier: =S-TAB=, =S-<up>=, =M-S-RET=.

A backslash in a basic string must be doubled. These two lines are the same key, =⌃⌘\=:

#+BEGIN_SRC toml
keys = "C-s-\\"
keys = 'C-s-\'
#+END_SRC

** Priority

Bindings are read in order: the preset first, then your file from top to bottom. When several bindings have the same keys, later ones are tried first. A binding in your file without =when= therefore takes its keys everywhere, hiding every context-specific preset binding for them. A binding with =when= is tried first only in its context; elsewhere the preset's bindings still apply.

#+BEGIN_SRC toml
# M-RET in a table inserts a row; on headings and items it does what the preset says.
[[bind]]
keys = "M-RET"
command = "org.table.insert-row"
when = "table"
#+END_SRC

** Unbinding

Set =command= to ="none"= to remove a key. A ="none"= binding without =when= hides every earlier binding of exactly those keys, so the key goes to the text system (or, in the Doom preset, to Vim):

#+BEGIN_SRC toml
# Leave C-t to macOS's transpose and C-k to its kill.
[[bind]]
keys = "C-t"
command = "none"
[[bind]]
keys = "C-k"
command = "none"
#+END_SRC

Limitations:

- A ="none"= binding with =when= has no effect. You cannot unbind a key in one context only; bind it to another command in that context instead.
- Unbinding a prefix does not remove the longer sequences under it. Unbinding =C-c C-x= leaves =C-c C-x C-i= and the rest working. Unbind each sequence you want gone.

** Doom states

In the Doom preset every binding belongs to a state. A binding without =mode= never runs in the Doom preset, and a binding with =mode= never runs in the Emacs or Mac preset. =mode = "visual"= covers visual, visual-line and visual-block. To bind a key in more than one state, write one table per state:

#+BEGIN_SRC toml
# SPC n a opens the agenda.
[[bind]]
keys = "SPC n a"
command = "app.agenda"
mode = "normal"

# C-c n inserts a heading in normal and insert state.
[[bind]]
keys = "C-c n"
command = "org.heading.insert"
mode = "normal"
[[bind]]
keys = "C-c n"
command = "org.heading.insert"
mode = "insert"
#+END_SRC

A =mode= other than =normal=, =insert= or =visual= (including =visual-line=) is reported when the file loads, and the binding is skipped.

** More examples

#+BEGIN_SRC toml
# Mac preset: ⌃⌘U goes up to the parent heading, ⌃⌘R opens column view, ⌃⌘; toggles COMMENT.
[[bind]]
keys = "C-s-u"
command = "org.heading.up"
[[bind]]
keys = "C-s-r"
command = "org.columns"
[[bind]]
keys = "C-s-;"
command = "org.heading.toggle-comment"

# Emacs preset: C-c b opens the board, C-c r reloads this file.
[[bind]]
keys = "C-c b"
command = "app.board"
[[bind]]
keys = "C-c r"
command = "app.reload-keymap"

#+END_SRC

** Reloading and errors

Orgstar watches the configuration folder and reloads =keymap.toml= when you save it. It also reloads when you change the preset, and when you run Reload Keymap (=app.reload-keymap=, in the palette, and =SPC h r r= in Doom normal state), which shows =Keymap reloaded=.

Problems are reported in the echo area with the line number, for example =keymap.toml: line 12: unknown context tabel (and 1 more)=. A binding with bad or missing =keys=, a missing =command=, a command id Orgstar does not know, an unknown =when= or =mode=, or a table other than =[[bind]]= is skipped; the rest of the file still applies. A file that is not valid TOML is ignored as a whole and the error is shown; the preset alone applies until you fix it.

** Importing from Emacs

Settings ▸ General ▸ Import from Emacs… reads your Emacs or Doom configuration and offers, among other things, the key bindings it finds: =global-set-key=, =keymap-global-set=, =define-key=, =keymap-set=, =evil-define-key= and Doom's =map!= with =:leader=, =:localleader=, state keywords and =:prefix=. Bindings to commands Orgstar has are appended to =keymap.toml= under a =# Imported from Emacs.= comment, leaving out bindings the file already has. Keys written as vectors, such as =[f5]=, are skipped. See [[file:15-alongside-emacs.org][Alongside Emacs]].

* Vim editing (Doom preset)

The Doom preset edits modally, as Doom Emacs does with =evil=, =evil-org=, =evil-surround=, =evil-snipe= and =evil-nerd-commenter=. Orgstar implements these itself; none of them are Emacs packages running inside it. The caret is a block in normal and visual states and a bar in insert state, and the modeline shows the state.

** How keys are handled

Each key goes first to the keymap for the current state, then to the Vim engine:

1. Keys with =⌘= go to the menus.
2. If a Vim command is half typed (after =d=, ="a=, =3= and so on), the key goes to Vim.
3. Otherwise the keymap gets the key. A prefix such as =SPC=, =g=, =z=, =[=, =]=, =C-c= or =C-x= waits for the next key, with key hints as described above. A complete sequence runs its command if the binding's context holds and the command can run at the caret.
4. Anything the keymap does not take goes to Vim, as typed. In insert state, keys Vim does not handle are typed as text.

Two consequences:

- Keymap commands do not take counts or registers. Once you type a count or a register, the following keys go straight to Vim.
- A sequence the keymap does not complete after =SPC=, =C-c=, =C-x= or another Control or Meta prefix is undefined: the echo area shows, for example, =SPC j is undefined=, and nothing runs. After =g=, =z=, =[= or =]=, which are Vim prefixes too, the keys are replayed into Vim, so =gu= and =gq= reach the Vim engine although the keymap binds other =g= keys.

** States

| State | Enter with | Leave with |
|-+-+-|
| Normal | =ESC=, =C-[= or =C-g= from insert state; =ESC= from visual | — |
| Insert | =i=, =a=, =I=, =A=, =o=, =O=, =c= commands, =cc=, =C=, block =I=, =A=, =c= | =ESC=, =C-[=, =C-g= |
| Visual | =v= | =v=, =ESC= |
| Visual line | =V= | =V=, =ESC= |
| Visual block | =C-v= | =C-v=, =ESC= |

Leaving insert state moves the caret back one character, as in Vim. A mouse click leaves visual state. In the keymap, ="visual"= is the state name for all three visual states.

In insert state, =C-w= deletes the word before the caret and =C-u= deletes back to the line's indentation (or to the start of the line when the caret is already there). The rest of insert state is the Emacs preset's Org keys, the Doom insert-state keys in the reference (=TAB= and =S-TAB= on headings, items and tables, =C-t= and =C-d=, =C-S-h/j/k/l=, =C-SPC= for completion) and ordinary typing.

** Motions

Motions move the caret in normal state, extend the selection in visual states, and give the range for an operator. A count before a motion repeats it.

| Keys | Moves |
|-+-|
| =h=, =l=, =<left>=, =<right>=, =DEL= | Left, right; =DEL= is =h=. Stays on the line. |
| =j=, =k=, =<down>=, =<up>= | Down, up, keeping the column. |
| =gj=, =gk= | In Org files, to the next or previous Org element (=org-forward-element=, =org-backward-element=, as evil-org binds them); counts are ignored. On a heading, =gj= goes to the next heading after the subtree and =gk= to the previous heading at the same level or higher. In other files, down and up by screen lines in wrapped text. |
| =+=, =-=, =RET= | First non-blank of the next or previous line. In Org files =RET= runs Act at Point instead. |
| =w=, =b=, =e=, =ge= | Next word start, previous word start, word end, previous word end. |
| =W=, =B=, =E=, =gE= | The same for blank-separated WORDs. |
| =0=, =<home>= | Start of the line. |
| =^= | First non-blank of the line. |
| =$=, =<end>= | End of the line; with a count, of the line count − 1 lines down. |
| =g_= | Last non-blank of the line. |
| =gg=, =G= | First line, last line; with a count, that line. The column is kept (=evil-start-of-line= nil). |
| =f= /x/, =F= /x/, =t= /x/, =T= /x/ | To, or to just before, the next or previous /x/ on the line. These are one-character snipes, as Doom's =evil-snipe-override-mode= makes them. /x/ also matches its accented and other variants, as Doom's =evil-snipe-char-fold= makes it: =a= matches =à=, =À=, =ª= and =ａ=. A lowercase /x/ matches either case, a capital only capitals; =t= and =T= skip a match right next to the caret; =f SPC= and =t SPC= skip a run of blanks after the caret and stop at the last blank before the next word, or just before it. |
| =;=, =,= | Repeats the last snipe (=s=, =S=, =f=, =F=, =t= or =T=), forward or reversed. A repeat searches all the text the window shows, so it can go past the caret's line (=evil-snipe-repeat-scope=, as Doom sets it). Right after a snipe, its own key repeats it: =f= goes on in the same direction and =F= reverses, and the same for =t= and =T= and for =s= and =S=. A count typed right after a snipe ends this: the key after the count starts a new snipe with that count, so =f a 2 f a= goes to the next /a/, then to the second /a/ after it. |
| =s= /xy/, =S= /xy/ | evil-snipe: to the next or previous /xy/ on the line. Each character matches its variants as for =f=, and /xy/ without a capital matches case-insensitively. =SPC= and =TAB= are read as a space and a tab. Not available after an operator. |
| =%= | The bracket matching the next =()=, =[]= or ={}= on the line. |
| ={=, =}= | Previous, next blank line. |
| =/=, =?= | Asks in the echo area for a regular expression and searches forward or backward, wrapping around the file. |
| =n=, =N= | Repeats the last search in the same or the opposite direction. |
| =*=, =#= | Searches forward or backward for the whole word under the caret. |
| =C-d=, =C-u= | Down, up half the window's height; with a count, that many lines. |
| =H=, =M=, =L= | First non-blank of the top, middle or bottom line the window shows. With a count, =H= goes to that line from the top and =L= from the bottom. Lines are text lines, not wrapped screen lines. Linewise after an operator. |
| ='= /a/, =`= /a/ | To mark /a/: its line's first non-blank, or its exact position. See [[*Marks and jumps][Marks and jumps]]. |

Search patterns are ICU regular expressions as macOS uses them, close to PCRE; Emacs and Vim regexp syntax such as =\(...\)= or =\<= does not work. =:noh= is accepted and does nothing; searches are not highlighted.

** Operators

| Keys | Does |
|-+-|
| =d= /motion/ | Deletes. =dd= deletes lines. |
| =c= /motion/ | Deletes and enters insert state. =cc= keeps the line's indentation; =cw= changes to the end of the word, as =ce=. |
| =y= /motion/ | Yanks (copies). =yy= yanks lines. |
| =>= /motion/, =<= /motion/ | Indents or outdents lines by 8 spaces (=evil-shift-width=, which Doom sets to Org's =tab-width=). =>>= and =<<= act on lines. |
| =g~= /motion/, =gu= /motion/, =gU= /motion/ | Toggles case, lowercases, uppercases. =g~~=, =guu=, =gUU= act on lines. |
| =gc= /motion/ | Comments or uncomments lines with =#= (=evilnc-comment-operator=). =gcc= acts on lines. See [[*Commenting][Commenting]]. |
| =gq= /motion/, =gw= /motion/ | Fills the paragraphs in the motion's lines to the fill column, as Fill Paragraph does; other elements in the lines are left alone. =gq= leaves the caret on the first non-blank of the last line, =gw= where it was. ** Counts and registers

A count is digits before a command; =0= only counts after another digit. A register is ="= and a name before the count and command: ="ayy=, ="a3dd=, ="ap=.

| Register | Holds |
|-+-|
| ="a= to ="z= | Named registers. Yanking or deleting into =A= to =Z= appends to the lowercase one. Writing to a named register leaves the clipboard alone. |
| ="0= | The last yank. |
| =""=, ="+=, ="*= | The system clipboard. This is the unnamed register: every yank, delete and change without a register goes to the clipboard, and =p= without a register pastes from it. |
| ="_= | The black hole: deletes without saving the text. |

Pasting from the clipboard is linewise when its text is what the last linewise yank or delete put there; text copied in another app pastes as characters. Numbered registers ="1= to ="9=, and the read-only registers such as ="%=, are not available.

Registers and macros are shared by every buffer, as in evil: a yank into ="a= in one file pastes with ="ap= in another. Lowercase marks and the jump list belong to the buffer and are gone when it closes. Nothing is kept when Orgstar quits.

** Repeat

=.= repeats the last change made in normal state, including text typed in insert state that the change began: =ciwfoo ESC= then =.= changes the next word to =foo=. A count before =.= replaces the original count.

Changes made from visual or visual-block state, visual =S= surrounds, and keymap commands (such as =M-l= or =SPC m t=) are not repeated by =.=.

** Macros

| Keys | Does |
|-+-|
| =q= /a/ | Starts recording keys into macro register /a/ (a letter or digit). The echo area shows =Defining keyboard macro…=. |
| =q= | Stops recording: =Keyboard macro defined=. |
| =@= /a/ | Plays macro /a/. A count plays it that many times. |
| =@@= | Plays the last macro played. |

A macro replays the keys you typed, including keymap commands, leader keys and insert-state typing. Keys with =⌘= are not recorded. Macros are kept apart from text registers: ="ap= does not paste a macro, and ="ay= does not change one. Macros can call macros up to 20 deep.

** Marks and jumps

=m= /a/ sets mark /a/ (any letter) at the caret. Marks move with the text as you edit. ='= /a/ goes to the first non-blank of the mark's line, =`= /a/ to its exact position. =''= and =``= go back to where the last jump started.

Jumps are =G=, =gg=, =%=, ={=, =}=, =n=, =N=, =*=, =#=, ='=, =`=, =H=, =M=, =L=, the snipes =s=, =S=, =f=, =F=, =t= and =T=, and searches with =/= and =?=. Each jump adds its starting point to the jump list, which keeps the last 100. =C-o= goes back through the list and =C-i= forward again. A new jump after =C-o= drops the places you went back past.

Lowercase marks belong to the buffer, and so do =C-o= and =C-i=. Uppercase marks (=mA= to =mZ=) are file marks, shared by every buffer: ='A= or =`A= in another buffer shows the buffer the mark was set in, at the mark. A file mark goes away when its buffer closes.

* iOS and iPadOS

With a hardware keyboard, the iOS app runs the Emacs preset's bindings, whatever preset the Mac uses. It does not read =keymap.toml= and has no Vim editing.

- Keys with =⌘= are left to iOS.

Doom keys marked (N), (I) or (V) work only in normal, insert or visual state; unmarked ones work in all three.

When a key appears in several rows, it runs the command whose condition holds at the caret: for example =M-<right>= demotes a heading, indents a list item and moves a table column. The descriptions say where each one applies. Movement and text editing in the Doom preset are the Vim keys above, so the Doom column is empty for those rows.
